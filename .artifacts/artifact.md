# Artifact Synchronization Specification

## Purpose
To permanently persist the ephemeral "thought process" and planning artifacts generated by AI agents (e.g., `task.md`, `implementation_plan.md`, `walkthrough.md`) into the project's codebase. This ensures that the context and reasoning behind code changes are preserved alongside the code itself.

## Protocol

### Trigger
The user triggers this workflow by tagging `@artifact.md` in a thread or explicitly requesting to save artifacts.

### Action
The agent must copy the current versions of all active artifacts to the `.artifacts/` directory.

### Storage Structure
Artifacts are stored in a subdirectory named after the Issue ID or Conversation ID.

**Path Format:**
`.artifacts/<issue-id>/`

**Files to Sync:**
- `task.md`
- `implementation_plan.md`
- `walkthrough.md`

### Example
If the conversation ID is `change-plaid-mutation` and the user tags `@artifact.md`, the agent creates:
- `.artifacts/change-plaid-mutation/task.md`
- `.artifacts/change-plaid-mutation/implementation_plan.md`
- conversation ID must be human readable and descriptive of the chat/issue solved
