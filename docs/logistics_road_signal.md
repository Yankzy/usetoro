# Product Requirements Document (PRD)

Project: Toro Logistics - Community Gravity Engine
Module: The Road Signal (v1.0)
Objective: Create a weekly, data-driven intelligence dispatch that becomes culturally central to the carrier ecosystem, driving viral adoption of the Compliance OS.
Status: APPROVED FOR DEVELOPMENT

1. Executive Summary

Strategic Intent: "The Road Signal" is not a newsletter, a forum, or a social network. It is a deterministic, statistical weekly dispatch generated from the anonymized, aggregated data collected by the Toro Compliance OS (Phase 1).
The Goal: Build community identity, establish status, and create anticipation. By paywalling the full intelligence report behind "Carrier Verification," we use The Road Signal as a high-value lead magnet to force carriers to connect their ELDs or upload Rate Confirmations, instantly bootstrapping our core data moats.

2. Access Model & The Data Paywall (The Wedge)

Objective: Use the intelligence generated by existing users to acquire new users.

REQ 2.1 - The Teaser (Public/Unverified): Unverified users and the general public can only view the "Headline Summary" and the "Prediction Poll" via web or SMS.

REQ 2.2 - The Paywall Gate: To unlock the full WeeklySignal report (Broker Payment Watch, Lane Heatmaps, Whisper Index), a user MUST have a compliance_state = ACTIVE (See Phase 1 PRD).

REQ 2.3 - Verification Trigger: If an unverified user clicks "Read Full Report", the UI strictly enforces the onboarding flow:

Input USDOT Number.

Connect ELD via OAuth OR upload at least one valid Rate Confirmation PDF.

3. Epic 1: The Weekly Generation Engine

Objective: Automatically aggregate and compute industry intelligence from Toro's internal databases with zero manual human input.

REQ 3.1 - The Trigger: A background cron job initiates the GenerateSignal pipeline every Sunday at 02:00 UTC.

REQ 3.2 - Delta Calculations: The Metrics Calculation Engine must compute weekly deltas based on Phase 1 tables:

BrokerPaymentTrend = AvgDaysToPay_current_week - AvgDaysToPay_previous_week (From broker_payment_records).

LaneMomentumScore = AvgRatePerMile_current - AvgRatePerMile_4week_avg (From extracted Rate Confirmations).

EnforcementSpikeIndex = ComplianceViolations_current_week / trailing_average (From carrier_profiles state changes).

REQ 3.3 - Anonymization & Minimum Thresholds: To prevent exposing individual carrier data, the system MUST drop any metric block that relies on a dataset of < 20 independent records.

4. Epic 2: AI Narrative & Report Structure

Objective: Translate raw SQL outputs into readable, factual, non-sensational insights.

REQ 4.1 - AI Summary Generator: Feed the computed metrics into an LLM with strict system prompts: "Transform this data into factual, objective statements. No sensationalism. No accusations." * Input: AvgDaysToPay increased from 32 to 38.

Output: `"Industry payment speed slowed this week, with average settlement time rising by 6 days."*

REQ 4.2 - Section Generation: The final WeeklySignal JSON object must contain 5 distinct structures:

Payment Watch: Top 5 fastest/slowest paying brokers + Industry average.

Lane Heatmap: Top rising/declining lanes and deadhead risk zones.

Compliance Watch: Spikes in insurance lapses and DOT suspensions.

Carrier Archetypes: K-means clustering of carriers (e.g., "High-margin regional" vs "Detention-heavy"). Highlights what the top 10% did differently.

The Whisper Index: Statistically significant (n >= 20) structured complaints (e.g., rate renegotiation spikes).

REQ 4.3 - The Legal Gate: The generated report MUST be staged with status = PENDING_REVIEW. An internal Toro admin must flag it as APPROVED before distribution to ensure broker names are legally safe to publish.

5. Epic 3: Community Mechanisms (Status & Anticipation)

Objective: Give carriers a reason to care, compete, and return every week.

REQ 5.1 - Signal Badges (Status): * Background worker evaluates carrier performance metrics (Phase 1 Performance Score).

If a carrier is in the 80th percentile or above, grant the "Signal Verified Performer" database flag.

Render a high-fidelity, un-copyable badge on their in-app profile. (This seeds the trust layer for Phase 3 Shipper matching).

REQ 5.2 - Prediction Poll (Anticipation):

Include a binary signal_polls object in each weekly report (e.g., "Will Southeast dry van rates increase next week?").

Expose an API endpoint for verified carriers to cast a YES/NO vote.

Resolve and publish the results in the following week's report.

6. Epic 4: Distribution Architecture

Objective: Deliver the signal through high-engagement, scarcity-driven channels.

REQ 6.1 - SMS Teaser: On Sunday at 08:00 Local Carrier Time, fire an SMS via Twilio to all opted-in carriers: "The Road Signal: Dry van rates dropped 4% in the Midwest. 2 brokers flagged for late payments. Tap to read full report: [Unique_Link]"

REQ 6.2 - In-App Rendering: Render the report within the Toro Compliance OS mobile/web dashboard.

REQ 6.3 - Scarcity Enforcement: Do NOT publish the report to public web pages, Facebook, or Twitter. The URL must require an authenticated session. Scarcity increases status.

7. Data Architecture Requirements

-- The Immutable Weekly Report
CREATE TABLE weekly_signals (
    id UUID PRIMARY KEY,
    week_number INT NOT NULL,
    year INT NOT NULL,
    generated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    metrics_snapshot JSONB NOT NULL,
    narrative_summary TEXT,
    status VARCHAR(20) DEFAULT 'PENDING_REVIEW', -- PENDING_REVIEW, PUBLISHED
    UNIQUE(week_number, year)
);

-- Anticipation Mechanics
CREATE TABLE signal_polls (
    id UUID PRIMARY KEY,
    weekly_signal_id UUID REFERENCES weekly_signals(id),
    question TEXT NOT NULL,
    yes_votes INT DEFAULT 0,
    no_votes INT DEFAULT 0,
    resolved_answer BOOLEAN DEFAULT NULL
);

-- Status Mechanics
CREATE TABLE carrier_badges (
    id UUID PRIMARY KEY,
    carrier_id UUID REFERENCES carrier_profiles(id),
    badge_type VARCHAR(50) DEFAULT 'TOP_20_PERFORMER',
    awarded_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    expires_at TIMESTAMP -- Badges should expire to force continued good behavior
);


8. Success Metrics (KPIs)

The Hook (Acquisition): >15% conversion rate of Unverified users hitting the paywall to uploading an ELD/Rate Con.

The Habit (Retention): >60% weekly open rate; Average Time on Page > 3 minutes.

The Cultural Moat: Number of organic inbound requests referencing "The Signal" or "Signal Verified" badges.
