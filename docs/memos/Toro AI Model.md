# Internal Strategy Memo: The Five-Year Path to a Toro-Owned Intelligence Layer

**Date:** August 2026
**Horizon:** 2026 to 2031
**Purpose:** Define the strategic path by which Toro evolves from a model-consuming agent platform into an agent platform with its own economically viable intelligence layer.

## Executive Thesis

We should not attempt to build a foundation model today.

Our immediate objective is to build the **agent network, enterprise state infrastructure, verification systems, and economic activity** that will eventually make owning a model economically inevitable.

Today, frontier model providers supply intelligence to our platform. Five years from now, the goal is for Toro to supply the majority of intelligence required by its own agent network through a proprietary model layer, while continuing to use frontier providers for difficult or novel tasks.

The strategic asset is therefore not initially the model.

**The strategic asset is the verified dataset of autonomous enterprise work that makes the model possible.**

---

# Year 1: Build the Work Infrastructure

### Objective

Make Toro the infrastructure through which enterprise work is executed by agents.

The priority is not model training. It is making the harness exceptionally good at executing, observing, verifying, and recovering from real work.

### Build

* Enterprise State Engine
* Agent-to-agent communication
* Persistent enterprise memory
* Permissions and authorization
* Workflow orchestration
* Verification and reconciliation
* Human escalation
* Agent telemetry
* Enterprise integrations
* ToroDB
* Economic accounting for agent execution

Every agent action should produce structured telemetry.

We should know:

* what the agent was trying to accomplish
* what state it observed
* what tools it used
* what action it took
* what evidence supported the action
* whether the action was verified
* whether it failed
* whether a human intervened
* what ultimately happened

### Model strategy

Use frontier providers aggressively.

Do not optimize prematurely for owning inference.

At this stage, intelligence is a purchased commodity.

### Strategic milestone

**Toro becomes the system of record for autonomous enterprise work.**

---

# Year 2: Turn Agent Activity Into Training Data

### Objective

Convert the agent network from merely an execution system into a continuously improving intelligence system.

The critical realization should be:

> Every completed workflow is potentially a training example.

Instead of storing only conversations, capture complete trajectories:

**Enterprise state → task → agent actions → tool calls → evidence → verification → outcome**

Begin constructing datasets around:

* successful trajectories
* failed trajectories
* corrected trajectories
* human interventions
* tool-use patterns
* agent-to-agent interactions
* verification outcomes
* uncertainty
* recovery strategies

### Build

Create an internal **Toro Intelligence Dataset**.

The dataset should be:

* structured
* versioned
* anonymized where appropriate
* quality-scored
* linked to verified outcomes
* partitioned by domain
* traceable back to the originating workflow

Begin training small models for narrow tasks where economics justify it.

Examples:

* classification
* entity resolution
* extraction
* routing
* reconciliation
* anomaly detection
* confidence estimation

### Model strategy

The frontier models remain the primary reasoning layer.

But Toro begins learning which intelligence should be purchased and which intelligence should be generated internally.

### Strategic milestone

**Toro begins converting operational activity into proprietary intelligence.**

---

# Year 3: Build the Toro Agent Model

### Objective

Move from specialized models toward a general-purpose model optimized for enterprise agent work.

At this point, the question changes from:

> "Can we train a model?"

to:

> "Which percentage of our workload can we perform more cheaply and reliably with our own model?"

We should benchmark our internal model against actual production workloads.

Not generic benchmarks.

The relevant benchmark is:

**Can Toro's model successfully complete Toro's work?**

### Model characteristics

The model should be optimized for:

* tool use
* structured outputs
* enterprise terminology
* workflow execution
* state awareness
* agent-to-agent communication
* verification
* recovery
* deterministic behavior where required
* low latency
* low inference cost

It does not need to outperform frontier models at everything.

It needs to outperform them economically on **Toro's workload distribution**.

### Architecture

Introduce model routing:

**Toro Model**

for routine and well-understood work.

**Frontier Models**

for difficult, novel, ambiguous, or high-complexity work.

The harness decides which model is appropriate.

### Strategic milestone

**Toro becomes its own primary inference provider for a meaningful percentage of production work.**

---

# Year 4: Optimize the Intelligence Economy

### Objective

Turn the model layer into a competitive economic advantage.

By this stage, millions of agent actions should provide enough operational data to understand the exact economics of intelligence.

We should know:

* cost per task
* tokens per task
* latency per task
* success rate
* human intervention rate
* verification rate
* model escalation rate
* cost of failure
* cost of frontier inference
* cost of Toro inference

Now optimize the entire stack around **cost per successfully completed task**, not cost per token.

### Model hierarchy

The production architecture should increasingly resemble:

**Toro Base Model**

Handles the majority of routine enterprise intelligence.

**Toro Domain Models**

Accounting, procurement, logistics, legal operations, insurance, etc.

**Enterprise Adaptation**

Enterprise-specific knowledge and behavior.

**Frontier Escalation**

Used only when Toro's internal intelligence is insufficient.

### Economic objective

Every year, increase:

**% of work completed by Toro models**

while maintaining or improving:

**accuracy, reliability, verification and enterprise trust.**

### Strategic milestone

**Model ownership becomes economically superior to buying all intelligence externally.**

---

# Year 5: Toro Intelligence Layer

### Objective

Make intelligence a native layer of the Toro platform.

At this point, Toro is no longer fundamentally a consumer of third-party intelligence.

It owns a complete intelligence stack:

**Enterprise State**

↓

**Agent Network**

↓

**Toro Intelligence**

↓

**Domain Intelligence**

↓

**Verification**

↓

**Economic Settlement**

↓

**Frontier Intelligence when necessary**

Third-party frontier models remain important, but they become complementary infrastructure rather than the foundation of the platform.

---

# The Five-Year Flywheel

The strategy depends on a compounding loop.

**More enterprises**

↓

**More autonomous work**

↓

**More verified agent trajectories**

↓

**More proprietary training data**

↓

**Better Toro models**

↓

**Lower inference cost**

↓

**Cheaper autonomous work**

↓

**More economically viable agents**

↓

**More enterprises**

The model therefore becomes stronger because the network becomes larger.

And the network becomes more valuable because the model becomes stronger.

---

# What We Should Not Do

We should explicitly avoid several mistakes.

### 1. Do not train a foundation model too early

Owning a model before we have the workload, data and economics is an expensive distraction.

### 2. Do not compete with frontier labs on generic intelligence

Our advantage is not "Toro knows more facts than everyone else."

Our advantage is:

**Toro knows how autonomous enterprise work gets done.**

### 3. Do not optimize for benchmark performance

The benchmark that matters is successful completion of real enterprise tasks.

### 4. Do not discard failed trajectories

Failures, corrections and recoveries may be more valuable than successful outputs because they teach the model what not to do.

### 5. Do not treat telemetry as observability alone

Telemetry should eventually become the raw material for model improvement.

The telemetry system is therefore part of the intelligence infrastructure.

---

# The Strategic Moat

The ultimate moat is not simply the model.

A competitor can potentially download an open-weight model.

They cannot easily reproduce:

* millions of enterprises
* millions of agents
* years of workflow trajectories
* verified outcomes
* enterprise state
* agent-to-agent interactions
* proprietary integrations
* permission structures
* economic transactions
* failure and recovery histories

The model sits on top of this accumulated infrastructure.

That is why **the network must come first.**

---

# The Five-Year Destination

By 2031, the goal is not merely:

> "Toro has its own LLM."

The goal is:

> **Toro owns the intelligence substrate that powers an autonomous economic network.**

Third-party frontier models remain available as specialists.

But the default intelligence layer is Toro.

The platform earns from autonomous work while simultaneously generating the data required to make autonomous work cheaper, more reliable and more capable.

That creates a compounding advantage:

**Work creates data.
Data creates intelligence.
Intelligence creates cheaper work.
Cheaper work creates more agents.
More agents create more work.**

The model is therefore not the starting point of the strategy.

**It is the consequence of winning the agent network.**
