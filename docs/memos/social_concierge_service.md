# **INTERNAL ENGINEERING & OPS MEMO: TORO OS**
**DATE:** April 8, 2026
**TO:** Engineering (Backend/UI) & Operations
**PREREQUISITE READING:** *Internal Strategy Memo - Architecture of the "Fractional CMO" Social Distribution Engine*
**SUBJECT:** Architecture of the "Engagement Sniper" HITL Proxy Dashboard

**1. EXECUTIVE SUMMARY**
Building directly upon the outbound infrastructure established in the **Fractional CMO Module**, Toro OS is launching the inbound processing engine: a premium $1,500/month "Done-For-You" Social Media Concierge service. To execute this with high margins, we are deploying a Human-in-the-Loop (HITL) operational team to manage the incoming engagement generated by the Fractional CMO's automated posts. 

**CRITICAL SECURITY MANDATE:** Under no circumstances will any Toro OS worker have direct login credentials to a client’s LinkedIn, X, or Facebook account. Engineering will build an **Internal Proxy Dashboard** to strictly sandbox the workers, leveraging the exact OAuth 2.0 database already built for the Fractional CMO module.

**2. THE PROXY DASHBOARD ARCHITECTURE (THE SECURE SANDBOX)**
The workflow must be completely decoupled from the native social media platforms.

* **Client Authentication (Shared OAuth):** We will utilize the same OAuth 2.0 access tokens generated when the CPA connected their accounts for the Fractional CMO module. No new authentication is required from the CPA.
* **Event-Driven Ingestion:** We will not use polling or web scraping. The Go backend will register Webhooks with the official social APIs. When a comment is posted on a CPA's feed, the platform pushes the payload directly to our server in milliseconds.
* **The Internal UI:** The Moroccan operator logs into `admin.toro-os.com`. They do not see the LinkedIn UI. They see a stripped-down, Kanban-style Toro OS dashboard displaying incoming comments as actionable "Tickets."

**3. THE AI EXOSKELETON WORKFLOW (THE ASSEMBLY LINE)**
The operator UI must be explicitly designed for workers without marketing degrees. The interface will restrict their actions to prevent errors.

* **Step 1 (Ingestion):** A ticket appears: *Comment from John Doe: "Does this apply to S-Corps?"*
* **Step 2 (AI Generation):** The operator clicks `Draft Reply`. The Go backend queries the LLM (using the exact same "CPA DNA Prompt" established in the Fractional CMO onboarding) to generate a professional, accurate response.
* **Step 3 (Human Review):** The operator reads the AI output. They act as the hallucination firewall. 
* **Step 4 (API Dispatch):** If accurate, the operator clicks `Publish`. The Go backend uses the shared OAuth token to POST the reply back to the social media API.

**4. ACCESS CONTROL & RISK MITIGATION**
* **Instant Revocation:** If an operator leaves the company, their Toro OS admin account is deactivated with one click. They lose all access to the queue, while the CPAs' native social media accounts remain perfectly secure.
* **Approval Gates:** For operators in their first 30 days of training, the `Publish` button will not send the reply to the API; it will send it to a Senior QA queue for a second set of human eyes.
