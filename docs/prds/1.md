# **OPERATIONAL PRD 1: TORO-001 (Liquidity & Tax-Harvesting Radar)**
**DATE:** April 10, 2026
**TARGET SYSTEM:** Toro OS (Go/NATS Core)
**OWNER:** Lead Backend Engineer / System Architect

#### **1. PRODUCT OBJECTIVE & ICP**
* **End-User:** High-Net-Worth Tech Founder (e.g., Sam Parr archetype).
* **Operator:** The 1-to-5 person CPA firm.
* **Problem:** The Founder has a massive quarterly tax liability approaching, but their capital is tied up in public equities, leaving their checking account dangerously low. 
* **Solution:** A deterministic alert system that cross-references upcoming tax liabilities (QuickBooks), current liquid cash (Plaid), and live stock portfolio performance (Alpha Vantage). If a cash shortfall is detected *and* a stock position is currently operating at a loss, the system alerts the CPA to propose a tax-loss harvesting maneuver to free up cash and lower the tax burden simultaneously.

#### **2. SYSTEM ARCHITECTURE & DATA SOURCES**


This feature requires three distinct data pipelines feeding into the Go/NATS core:

1.  **Liability Oracle (QuickBooks CDC via Go):**
    * Tracks accounts payable and upcoming estimated tax payments.
2.  **Liquidity Oracle (Plaid API via Python Microservice):**
    * Reads the real-time balance of the client's primary Chase/business checking accounts.
    * Reads the client's public brokerage holdings (Ticker symbols and Cost Basis via Plaid Investments API).
3.  **Market Oracle (Alpha Vantage API via Python Microservice):**
    * Streams real-time market prices for the specific ticker symbols held by the client.

#### **3. DETERMINISTIC LOGIC (THE GO BACKEND)**
The Go core engine must evaluate the following mathematical rule on a daily cron schedule (or whenever a new CDC event fires for tax liabilities):

* **Variable A (Cash):** `plaid.balance.available`
* **Variable B (Liability):** `quickbooks.liability.tax_estimated`
* **Variable C (Shortfall):** `Liability - Cash`
* **Condition 1 (Is there a problem?):** If `Shortfall > 0`, proceed to Condition 2.
* **Condition 2 (Is there a solution?):** Query Alpha Vantage for the live price of the user's holdings. Compare live price against the Plaid-ingested Cost Basis.
    * `if (live_price < cost_basis)` = **Unrealized Loss Detected**.
* **Execution Trigger:** If `Shortfall > 0` AND `Unrealized Loss > Shortfall`, publish event `alert.tax_harvest.ready` to NATS JetStream.

#### **4. MICROSERVICE ENGINEERING TASKS (PYTHON & GO)**

**Task 4.1: Alpha Vantage Python Microservice**
* **Action:** Build a stateless FastAPI or gRPC service.
* **Input:** Listens to NATS topic `market.price.request` containing a JSON payload of ticker symbols (e.g., `["TSLA", "META"]`).
* **Process:** Hits Alpha Vantage `GLOBAL_QUOTE` endpoint for those specific tickers.
* **Output:** Publishes JSON payload back to NATS topic `market.price.response`.
* *Rate Limit Note:* Alpha Vantage premium has high limits, but the Python script must batch requests to avoid network saturation.

**Task 4.2: Postgres Schema Updates (Go Core)**
* Create a `Client_Portfolios` table with Row-Level Security (RLS) tied to the CPA's ID.
* Fields required: `client_id` (UUID), `ticker_symbol` (String), `quantity` (Float), `cost_basis` (Float), `last_updated` (Timestamp).

**Task 4.3: NATS JetStream Topic Configuration**
* Create Stream: `TAX_RADAR`
* Subjects: `radar.evaluate.*`, `radar.alert.*`
* Retention Policy: `WorkQueue` (Ensures the Go backend only processes the shortfall evaluation once per trigger).

#### **5. UI/UX REQUIREMENTS (WAILS & REACT NATIVE)**

**CPA Interface (Wails Desktop App):**
* A new sidebar tab labeled: **"Liquidity Radar"**.
* Dashboard must display a ranked list of clients with triggered `alert.tax_harvest.ready` events.
* **UI Card details:** "Sam Parr is short $120,000 for Q3 taxes. TSLA position is down 14% ($150,000 unrealized loss). Click to generate Advisory Brief."
* **Action Button:** "Generate Client Brief" -> Triggers an LLM prompt (via Go backend) to draft a highly professional email explaining the tax-loss harvesting strategy, ready for the CPA to send.

**Client Interface (React Native Mobile App):**
* The client does *not* see the raw alert. They see a push notification triggered by the CPA: *"New Strategy Brief from your CPA regarding Q3 Taxes."*
* Clicking the notification opens the beautifully formatted PDF/text brief within the Toro OS secure mobile container.
