#### **1. PRODUCT OBJECTIVE & ICP**
* **End-User:** High-Net-Worth Tech Founder / SMB CEO.
* **Operator:** The 1-to-5 person CPA firm.
* **Problem:** Founders leave massive amounts of cash in 0% yield business checking accounts due to operational inertia, slowly bleeding purchasing power to inflation.
* **Solution:** A real-time, read-only dashboard that mathematically calculates "Inefficient Capital" by comparing bank balances against projected ledger burn rates. It queries live Treasury yield data to display exactly how much money the business is losing daily by not sweeping that cash into safe, short-term government bonds.

#### **2. SYSTEM ARCHITECTURE & DATA PIPELINE**


This feature acts as a deterministic calculator relying on three read-only data streams:
1.  **Liquidity Oracle (Plaid API via Python):**
    * Ingests the real-time available balance of the corporate checking account.
2.  **Burn Rate Oracle (QuickBooks CDC via Go):**
    * Calculates the trailing 90-day average monthly cash burn (Operating Expenses + Payroll). 
3.  **Yield Oracle (Alpha Vantage API via Python):**
    * Queries the `TREASURY_YIELD` endpoint (specifically 4-week or 3-month maturities) to establish the current risk-free rate.

#### **3. DETERMINISTIC LOGIC (THE GO BACKEND)**
The Go engine runs a continuous calculation whenever a new Plaid balance or QuickBooks CDC event fires:

* **Variable A (Available Cash):** `plaid.balance.available` (e.g., $2,000,000)
* **Variable B (Monthly Burn):** `quickbooks.expenses.90day_avg / 3` (e.g., $100,000/month)
* **Variable C (Safety Target):** Client-defined or CPA-defined runway (e.g., 6 months).
* **Variable D (Required Capital):** `Variable B * Variable C` (e.g., $600,000)
* **Variable E (Inefficient Capital):** `Variable A - Variable D` (e.g., $1,400,000)
* **Variable F (Current Yield):** `alpha_vantage.treasury_yield.3month` (e.g., 5.25%)
* **The Output (Lost Revenue):** `(Variable E * Variable F) / 365` = **Daily Lost Revenue** (e.g., $201.36 per day / $73,500 per year).

#### **4. MICROSERVICE ENGINEERING TASKS (PYTHON & GO)**

**Task 4.1: Postgres Schema Updates (Go Core)**
* Create `Capital_Efficiency_Settings` table. Fields: `client_id` (UUID), `target_runway_months` (Integer, default 6), `last_calculated_idle_cash` (Float), `last_calculated_lost_yield` (Float), `updated_at` (Timestamp).

**Task 4.2: Alpha Vantage Yield Microservice (Python)**
* **Input:** Scheduled daily cron job to run at market open.
* **Process:** Calls Alpha Vantage `function=TREASURY_YIELD&interval=daily&maturity=3month`.
* **Output:** Parses the JSON to extract the latest percentage yield and publishes to NATS JetStream: `macro.yield.updated`.

**Task 4.3: Efficiency Calculator Worker (Go)**
* Subscribes to `plaid.balance.updated`, `quickbooks.expenses.updated`, and `macro.yield.updated`.
* Whenever any of the three inputs change, recalculate the logic in Section 3.
* Update the Postgres state and publish `efficiency.dashboard.refreshed` to NATS to push the new numbers to the frontends.
