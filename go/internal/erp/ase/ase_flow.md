# ASE Execution Flow

This document maps out the precise lifecycle of data through the Autonomous Semantic Engine (ASE) package. It includes the exact file paths and line numbers mapping how nodes are created, wired, and executed in an asynchronous queue architecture.

> [!NOTE]
> All line numbers correspond to the current state of the codebase.

## 1. DAG Initialization & Startup
Before any transactions are processed, the DAG infrastructure must be constructed from `ase.yml`.

- **Where it starts:** `go/internal/workers/ase_bridge_worker.go`
  - **Line 63:** `w.dags = expirable.NewLRU[...]` initializes a thread-safe LRU cache that auto-evicts idle DAGs and safely tears down their background goroutines.
  - DAGs are no longer built entirely upfront. They are instead evaluated and lazy-loaded dynamically when events arrive.

- **Inside the DAG Engine:** `go/internal/erp/ase/dag.go`
  - **Line 544:** `BuildDAGFromConfig()` instantiates the nodes and maps relationships (`resolveChildren` at **line 588**).
  - **Line 186:** `StartAll()` iterates over every node and fires off an independent goroutine for each one.
  - **Line 188:** Calls `go n.flushLoop()`.

## 2. The Worker Consumes Data
Data enters the system via the NATS message queue, prompting the worker to pull database transactions.

- **Where it starts:** `go/internal/workers/ase_bridge_worker.go`
  - **Line 189:** `Handle()` is the main entry point for all NATS messages (both TAP workflow events and raw resume events).
  - **Line 398:** The worker dynamically looks up the requested DAG from the LRU cache (or compiles and starts it on the fly with `ase.BuildDAGFromConfig` and `dag.StartAll()`).
  - **Line 597:** `mapToAgent()` converts the database transaction payload into an `AutonomousSemanticEngineNode` (an agent).
  - **Line 466:** The worker fires off an asynchronous goroutine for the new agent and calls `a.Run(ctx, dagToUse, w.store)`.

## 3. Entering the DAG (Triaging)
The agent must find out which node in the DAG it belongs to.

- **Where it starts:** `go/internal/erp/ase/node.go`
  - **Line 315:** `Run()` immediately delegates to `Resume()`.
  - **Line 326:** `Resume()` is the main entry point for the agent's state machine.
  - **Line 350:** `entryNode = dag.Route(n)` evaluates the agent and decides it belongs in the `initial_router` entry node.
  - **Line 364:** `entryNode.Accept(n)` hands the agent over to the DAG.
  - **Line 370:** `Resume()` returns immediately. The worker goroutine is now completely unblocked.

## 4. The Infinite Queue & Flush Loop
The DAG nodes are essentially background workers holding queues of agents.

- **Where it starts:** `go/internal/erp/ase/dag.go`
  - **Line 201:** `Accept()` safely appends the agent into `dn.queue`.
  - **Line 215:** `flushLoop()` is the infinite `for` loop ticking every `batch_flush_seconds` (e.g. 5 seconds).
  - **Line 226:** `flush()` is called by the ticker. It locks the queue, extracts all agents into a `batch`, and clears the queue.
  - **Line 269:** It passes the agents down via `dn.ExecuteNode(batch)`.

## 5. Execution Phase (The Engine Logic)
This is where the actual LLM logic or routing logic evaluates the agents.

- **Where it starts:** `go/internal/erp/ase/dag.go`
  - **Line 273:** `ExecuteNode()` starts.
  - **Line 295:** `node.AppendExecutionStep()` records the agent's arrival in the trace array.
  - **Line 317:** Auto-advance logic checks if the node is allowed to proceed. If false, it calls `node.transition(StateHoldMissingCtx)` at **line 327**.
  - **Line 351:** `results, err := dn.thinkFn(dn.ctx, thinkingBatch)` is invoked. This executes the `BuildPayloadRouterThinkFunc` or LLM function generated by `classifier.go`.
  - **Line 389:** The results are injected back into the agent via `node.SetPropertyCandidates()`. (Inside `node.go` at **line 228**, this calculates the entropy and math algorithms).
  - **Line 391:** `dn.routeToChild(node, dn.Name)` tells the DAG to move the agent forward.

## 6. Routing to the Next Node
The agent has its classification and needs to move to the next step in the pipeline.

- **Where it starts:** `go/internal/erp/ase/dag.go`
  - **Line 412:** `routeToChild()` starts.
  - **Line 413:** `top := node.TopCandidate(propertyKey)` evaluates the highest confidence choice.
  - **Line 445:** `child, exists := dn.children[searchKey]` looks up the next node (e.g., `macro_classifier_outflow`).
  - **Line 458:** `node.UpdateLastExecutionStep()` completes the trace history for the *current* node, locking in the chosen edge.
  - **Line 468:** `child.Accept(node)` takes the agent and pushes it into the next node's queue.
  - **Cycle Repeats:** The process automatically jumps back to **Step 4**, but for the new node.

## 7. State Persistence
Anytime the agent changes state (e.g. gets held up, or finishes), it must save to PostgreSQL.

- **Where it starts:** `go/internal/erp/ase/node.go`
  - **Line 245:** `transition()` is called whenever the agent shifts states (like `StateActivating` -> `StateHoldMissingCtx`).
  - **Line 258:** `n.Persister.PersistNode(context.Background(), n)` fires.
  - **Where it saves:** The actual SQL execution happens in `aseStore.PersistNode()` inside `go/internal/workers/ase_store.go` (around **line 50**).
